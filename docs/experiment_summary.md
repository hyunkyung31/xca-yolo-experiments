# XCA 협착 탐지 실험일지

관상동맥조영술(XCA) 영상에서 협착 부위를 탐지하기 위해 진행한 데이터 분석, 이미지 전처리, YOLO 및 Faster R-CNN 실험 과정을 정리했습니다.

처음에는 작은 협착 부위의 탐지 성능을 개선하기 위해 영상 전처리에 집중했습니다. 이후 모델 구조와 학습 조건에 따른 차이를 비교하고, Segmentation과 ROI 기반 탐지 방식까지 확장해 보았습니다.

이 문서에는 주요 실험 설정과 결과뿐 아니라 진행 과정에서 발생한 문제, 해결 방법, 완료하지 못한 작업도 함께 정리했습니다.

전체 프로젝트의 주요 결과는 [README](../README.md)에서 확인할 수 있습니다.

## 1. 데이터 분석 및 협착 영역 확인

**관련 노트북:** `01_dataset.ipynb`

모델 학습에 앞서 ARCADE 데이터셋의 annotation 구조와 협착 영역의 크기를 확인했습니다.

COCO 형식의 JSON 파일을 불러와 이미지와 annotation의 개수를 확인하고, Bounding Box(bbox)의 면적과 너비, 높이 분포를 분석했습니다.

주요 데이터 구성은 다음과 같습니다.

| 항목 | 결과 |
|---|---:|
| 학습 이미지 | 1,000장 |
| 학습 협착 annotation | 1,625개 |
| 평균 bbox 면적 | 4,836.93 px² |
| 중앙값 bbox 면적 | 2,782.64 px² |
| 평균 bbox 너비 | 63.7 px |
| 평균 bbox 높이 | 66.9 px |

협착 annotation은 category ID 26을 기준으로 분석했습니다.

bbox 면적의 평균이 중앙값보다 높게 나타났으며, 비교적 작은 영역에 분포한 협착도 확인할 수 있었습니다. 이 때문에 영상 전체의 품질뿐 아니라 실제 병변 주변의 특징을 살펴볼 필요가 있다고 생각했습니다.

또한 일부 이미지에 bbox와 polygon을 시각화해 annotation이 영상의 어느 부분에 위치하는지 확인했습니다.

데이터 탐색 과정에서 조회한 전체 이미지 3,000장과 실제 협착 학습에 사용한 이미지 1,000장은 서로 다른 집계 범위입니다.

**참고 셀:** 15~16, 21, 25, 31

## 2. 이미지 전처리 방법 비교

**관련 노트북:** `02_preprocessing.ipynb`

작은 협착 부위의 특징을 강조하기 위해 영상의 명암 대비와 혈관 경계를 개선하는 전처리를 실험했습니다.

먼저 병변 bbox 주변에 40px의 여백을 두고 ROI를 추출했습니다. 이후 동일한 영역에서 전처리별 차이를 비교했습니다.

### 적용한 전처리

| 전처리 | 목적 |
|---|---|
| CLAHE | 국소 명암 대비 개선 |
| Gamma Correction | 영상 밝기 조절 |
| Frangi Filter | 혈관과 같은 선형 구조 강조 |
| Black-hat | 주변보다 어두운 구조 강조 |
| 조합 전처리 | 단일 기법을 결합했을 때의 변화 비교 |

Unsharp Mask와 Top-hat도 추가로 시각화하며 효과를 살펴봤습니다.

### 주요 전처리 설정

| 항목 | 설정 |
|---|---|
| CLAHE clipLimit | 2.0 |
| CLAHE tileGridSize | (4, 4) |
| Gamma | 0.8 |
| Frangi sigmas | 1~4 |
| Frangi gamma | 15 |
| Frangi black_ridges | True |
| Black-hat kernel | 15 |

다음 7가지 전처리를 배치로 적용했습니다.

1. CLAHE
2. Gamma
3. Frangi
4. CLAHE + Gamma
5. CLAHE + Gamma + Frangi
6. Gamma + CLAHE + Frangi
7. Black-hat

각 전처리에 대해 학습 이미지 1,000장과 검증 이미지 200장을 생성했습니다.

이 단계에서는 전처리 이미지 생성까지 진행했으며, 이후 YOLO 학습에 사용할 이미지와 라벨은 별도로 구성했습니다.

Unsharp Mask와 Top-hat은 시각화 단계에서만 비교했고, 위 7종의 배치 처리나 YOLO 학습 비교에는 포함하지 않았습니다.

**참고 셀:** 40, 44~45

## 3. 전처리 품질 평가

**관련 노트북:** `03_quality_metrics.ipynb`

전처리 결과를 육안으로만 평가하기에는 한계가 있다고 생각해 정량적인 영상 품질 지표를 계산했습니다.

영상 전체와 정답 병변 ROI를 대상으로 다음 지표를 사용했습니다.

- **Entropy:** 영상 정보량
- **Contrast:** 픽셀 밝기의 표준편차
- **Edge Density:** Canny Edge 검출 비율
- **Laplacian Variance:** 고주파 성분을 이용한 선명도 지표
- **Brenner Focus:** 인접 픽셀 밝기 차이를 이용한 초점 지표

Canny Edge의 threshold는 50과 150을 사용했습니다.

하나의 이미지에 여러 병변이 있는 경우 병변별 지표를 평균한 뒤 이미지 단위로 집계했습니다. 정답 병변이 없는 이미지는 ROI 지표에 0을 포함했습니다.

### 주요 결과

| 전처리 | ROI Contrast | ROI Edge Density | Global Laplacian Variance |
|---|---:|---:|---:|
| Original | 17.958918 | 0.074510 | 230.966124 |
| CLAHE | **34.135542** | **0.240672** | **548.082601** |
| CLAHE + Gamma | 32.315488 | 0.224897 | 521.803766 |

CLAHE를 적용했을 때 ROI Contrast는 Original보다 크게 증가했습니다. Edge Density와 Laplacian Variance도 높게 나타났습니다.

하지만 경계와 고주파 성분이 증가한 원인에는 영상 노이즈도 포함될 수 있습니다.

따라서 영상 품질 지표만으로 가장 좋은 전처리를 선택하지 않고, 실제 객체 탐지 모델의 성능까지 비교하기로 했습니다.

전체 품질 지표는 [실험 결과 CSV](../results/tables/03_quality_metrics__cell_007_output_03.csv)에 정리했습니다.

추가적인 전처리 순위와 종합 점수 계산은 구현했지만, 해당 계산의 실행 결과까지 확보하지는 못했습니다.

**참고 셀:** 5, 7, 9

## 4. YOLO 학습 데이터 구성과 오류 해결

**관련 노트북:** `03.5_Data Preparation.ipynb`

전처리한 영상을 YOLO 학습에 사용하기 위해 COCO annotation을 YOLO 형식으로 변환했습니다.

bbox 좌표를 정규화하고, 협착에 해당하는 category 26을 YOLO class 0으로 변경했습니다.

Faster R-CNN에는 배경을 class 0, 협착을 class 1로 구분해 적용했습니다.

### 초기 데이터 구성

| 항목 | Train | Validation |
|---|---:|---:|
| 원본 이미지 | 1,000 | 200 |
| 협착 bbox | 1,625 | 406 |
| 빈 라벨 이미지 | 3 | 0 |

### 검증 이미지 누락 문제

전처리 이미지 생성 후 YOLO 학습용 폴더를 구성했는데, 파일 개수를 확인하는 과정에서 문제가 발견됐습니다.

원본 데이터는 정상적으로 준비되었지만, 당시 점검한 전처리 6종의 검증 이미지 폴더에는 이미지가 없었고 라벨 파일만 200개 존재했습니다.

전처리 결과를 생성하는 경로와 실제 YOLO 학습에 사용하는 경로가 달랐기 때문입니다.

두 경로의 역할을 구분했습니다.

| 단계 | 경로 | 역할 |
|---|---|---|
| 전처리 | `data/preprocessed/<pipeline>/` | 전처리 이미지 생성 |
| YOLO 입력 | `data/yolo/<pipeline>/` | 학습 이미지와 라벨 구성 |

이후 실제 학습에 사용할 CLAHE와 CLAHE+Gamma 데이터를 다시 동기화했습니다.

각 입력에서 학습 이미지 1,000장과 검증 이미지 200장을 준비했고, Original을 포함한 세 가지 입력의 준비 상태가 `ready=True`인지 확인한 뒤 학습을 진행했습니다.

이 과정에서 **전처리 작업의 완료와 모델 학습 데이터 구성의 완료는 별도로 검증해야 한다는 점**을 배웠습니다.

CLAHE와 CLAHE+Gamma는 문제를 해결했지만, 나머지 전처리 전체를 같은 방식으로 복구한 것은 아닙니다.

**참고 셀:** `03.5`의 6, 8, 10 / `04`의 4~6

## 5. YOLO11n 전처리별 성능 비교

**관련 노트북:** `04_train_yolo(cursor).ipynb.ipynb`, `05A_yolo11_result_aggregation.ipynb`

영상 품질을 개선한 전처리가 실제 탐지 성능에도 도움이 되는지 확인하기 위해 YOLO11n으로 세 가지 입력을 비교했습니다.

### 학습 설정

| 항목 | 설정 |
|---|---|
| 모델 | YOLO11n |
| 사전학습 가중치 | 사용 |
| Epoch | 100 |
| Image Size | 640 |
| Batch Size | 16 |
| Seed | 42 |
| Validation | 이미지 200장, annotation 406개 |

### 최종 검증 결과

각 실험에서 선택된 `best.pt` 체크포인트를 검증한 결과입니다.

| 입력 데이터 | Precision | Recall | mAP50 | mAP50-95 |
|---|---:|---:|---:|---:|
| Original | 0.364 | 0.387 | 0.320 | 0.121 |
| CLAHE | 0.381 | 0.390 | 0.320 | 0.123 |
| CLAHE + Gamma | 0.381 | 0.387 | **0.330** | **0.127** |

CLAHE+Gamma가 세 가지 입력 중 가장 높은 mAP50-95를 보였습니다.

Original 대비 개선 폭은 0.006(0.6%p)이며, 상대적으로 약 4.96% 증가했습니다.

다만 영상의 대비와 경계 밀도가 증가한 정도에 비하면 탐지 성능의 개선 폭은 크지 않았습니다.

CLAHE 단독은 Original과 mAP50가 동일했고, CLAHE+Gamma도 작은 병변에 대한 탐지가 별도로 얼마나 개선됐는지는 추가 평가가 필요합니다.

### 평가 결과를 정리하면서 주의한 점

학습 결과를 비교하는 과정에서 서로 다른 지표 선택 기준이 사용된다는 점도 확인했습니다.

`05A`에서는 CSV에서 mAP50-95가 가장 높은 epoch를 선택했습니다.

| 입력 | 최고 epoch | mAP50-95 |
|---|---:|---:|
| Original | 74 | 0.12102 |
| CLAHE | 86 | 0.12320 |
| CLAHE + Gamma | 90 | 0.12703 |

한편 최종 비교 그래프는 `best.pt` 검증 로그의 0.121, 0.123, 0.127을 사용했습니다.

두 결과는 수치가 비슷하지만, 선택 기준과 정밀도가 다른 값이기 때문에 구분했습니다.

**참고 셀:** `04`의 4~7 / `05A`의 3~6

## 6. Faster R-CNN 및 YOLO 모델 크기 비교

**관련 노트북:** `05B_mmdet_swin_convnext.ipynb`

YOLO11n에서 전처리 효과를 비교한 뒤, 다른 탐지 모델에서도 비슷한 결과가 나타나는지 알아보기 위해 Faster R-CNN을 실험했습니다.

처음에는 MMDetection 기반 모델도 검토했지만 Python 3.12 환경에서 MMCV 의존성에 맞는 wheel을 구하기 어려웠습니다.

이에 torchvision의 Faster R-CNN 모델을 사용했습니다.

Faster R-CNN은 VOC 11-point AP50 방식으로 평가했으며, score threshold는 0.05로 설정했습니다.

### Faster R-CNN 결과

| 모델 및 입력 | Epoch | 최고 Epoch | 최대 AP50 | 마지막 AP50 |
|---|---:|---:|---:|---:|
| ResNet50-FPN / CLAHE+Gamma (별도 실행) | 100 | 4 | 0.310905 | 0.284617 |
| ResNet50-FPN / Original | 30 | 3 | 0.295686 | 0.255291 |
| ResNet50-FPN / CLAHE+Gamma | 30 | 4 | 0.290947 | 0.234812 |
| ResNet50-FPN-v2 / CLAHE+Gamma | 30 | 3 | 0.268508 | 0.216537 |
| MobileNetV3-FPN / CLAHE+Gamma | 미확정 | 5 | 0.185888 | 미확정 |

ResNet50-FPN의 30 epoch 실험에서는 Original이 CLAHE+Gamma보다 높은 AP50를 보였습니다.

이는 YOLO11n에서 CLAHE+Gamma가 가장 높았던 결과와 달랐습니다.

100 epoch로 별도 실행한 CLAHE+Gamma 모델은 AP50 0.310905를 기록했지만, 30 epoch 비교 실험과 동일한 조건으로 묶을 수는 없습니다.

일부 실험에서 동일한 출력 폴더명을 사용한 점도 결과를 정리할 때 주의해야 할 부분이었습니다.

MobileNetV3-FPN은 집계된 AP50와 체크포인트 정보만 있어 총 학습 epoch와 마지막 평가 결과를 확정하기 어렵습니다.

학습 loss가 감소하는 동안 검증 AP가 최고점 이후 낮아지는 구간도 나타났습니다. 다만 이 현상만으로 과적합의 구체적인 원인을 확정할 수는 없습니다.

### YOLO11n과 YOLO11s 비교

CLAHE+Gamma 데이터를 사용해 YOLO11n과 YOLO11s를 각각 50 epoch 학습했습니다.

| 모델 | Epoch | Precision | Recall | mAP50 | mAP50-95 |
|---|---:|---:|---:|---:|---:|
| YOLO11n | 50 | 0.346 | 0.404 | 0.296 | **0.122** |
| YOLO11s | 50 | 0.356 | 0.401 | **0.310** | 0.121 |

YOLO11s는 mAP50가 더 높았지만, mAP50-95에서는 YOLO11n보다 낮았습니다.

모델 크기를 키우면 항상 좋은 성능을 얻을 것이라고 생각하기 쉽지만, 이번 실험에서는 평가 지표에 따라 서로 다른 결과가 나타났습니다.

또한 이 실험은 앞서 수행한 YOLO11n의 100 epoch 전처리 비교와 학습 조건이 다릅니다.

Faster R-CNN과 YOLO의 AP 수치 역시 평가 방식이 달라 직접적인 모델 순위로 해석하지 않았습니다.

**참고 셀:** 7~9, 11

## 7. 커스텀 Backbone 구조 탐색

**관련 노트북:** `05C_yolo11_custom_backbone_skeleton.ipynb`

객체 탐지 모델의 Backbone을 변경하면 특징 추출 방식에 어떤 차이가 생길지 궁금해 추가 실험을 진행했습니다.

ConvNeXt, Swin, ViT를 참고해 특징 맵을 출력하는 합성곱 기반 스켈레톤과 TinyFPN을 구성했습니다.

이 단계의 목적은 외부 Backbone을 실제로 연결하기 전에 인터페이스와 특징 맵의 형태를 살펴보는 것이었습니다.

### 모의 학습

랜덤 이미지와 랜덤 타깃을 사용해 MSE 회귀 방식으로 간단한 학습 흐름을 테스트했습니다.

Loss는 다음과 같이 감소했습니다.

`4.5122 → 2.0322 → 1.2110`

다만 이 결과는 실제 협착 탐지 학습이 아니라 모델 연결 구조를 점검하기 위한 모의 실험입니다.

정식 Swin Transformer, ConvNeXt, ViT, InternImage Backbone을 탐지 모델에 통합하고 실제 ARCADE 데이터로 평가하는 단계까지는 진행하지 못했습니다.

별도로 실행한 기존 YOLO11n 50 epoch 실험의 결과는 다음과 같습니다.

| 모델 | Epoch | mAP50 | mAP50-95 |
|---|---:|---:|---:|
| YOLO11n / CLAHE+Gamma | 50 | 0.296 | 0.122 |

이 결과는 커스텀 Backbone의 성능이 아닙니다. 앞선 50 epoch 결과와 수치가 같지만, 독립적인 반복 실험으로 해석하기에는 실행 조건에 대한 추가 확인이 필요합니다.

**참고 셀:** 3, 6, 8~9

## 8. 확장 실험과 결과 집계 과정의 문제

### 8.1 추가 모델 학습 구성

**관련 노트북:** `05D_backbone_experiment_matrix.ipynb`

ResNet과 MobileNet 비교를 확장하기 위해 AdamW와 CosineAnnealingLR을 적용한 학습 코드를 구성했습니다.

YOLO 및 ConvNeXt를 선택할 수 있는 코드도 작성했지만, 실제 모델별 학습과 성능 비교까지 완료하지는 못했습니다.

실행 과정에서는 다음 오류가 발생했습니다.

`NameError: name 'random' is not defined`

선행 import가 실행되지 않아 작업이 중단됐으며, 전처리 데이터의 폴더 이름도 실제 경로와 달랐습니다.

- 코드의 참조 경로: `02_clahe_gamma`
- 실제 전처리 경로: `04_clahe_gamma`

이 부분은 아직 수정과 재실행이 필요한 상태입니다.

또한 정답 병변이 없는 이미지의 선택 방식이 이전 실험과 달라, 그대로 실행하더라도 완전히 동일한 조건의 모델 비교로 보기는 어렵습니다.

### 8.2 모델별 결과 집계

**관련 노트북:** `05E_compare_all_results.ipynb`

Faster R-CNN과 YOLO의 결과를 하나의 표와 그래프로 정리하는 작업도 진행했습니다.

이 과정에서는 다음 오류가 발생했습니다.

`NameError: name 'load_frcnn_rows' is not defined`

후속 셀에는 결과표와 그래프가 있지만, 전체 셀을 처음부터 다시 실행해도 동일하게 동작하는지는 아직 확인하지 못했습니다.

후속 집계에서 사용한 YOLO의 최고 mAP50는 0.345780이며, 해당 epoch의 mAP50-95는 0.12645입니다.

이 값은 mAP50를 기준으로 선택한 결과입니다.

앞서 `05A`에서 mAP50-95를 기준으로 선택한 결과와는 평가 기준이 다르므로 구분해서 정리했습니다.

## 9. Segmentation과 ROI 기반 탐지 확장

작은 병변의 탐지 성능을 높이기 위해 Segmentation 라벨 변환과 ROI 확대 방식을 추가로 구현했습니다.

이 단계에서는 데이터 변환과 추론 흐름의 코드를 구성했으며, 실제 ARCADE 데이터에 대한 모델 학습 및 최종 성능 평가는 완료하지 못했습니다.

### 9.1 COCO Polygon → YOLO Segmentation

**관련 자료:** `03.6_coco_to_yolo_seg.ipynb`, `06A_convert_coco_to_yolo_seg.py`

COCO annotation의 Polygon을 YOLO Segmentation 라벨 형식으로 변환하는 코드를 작성했습니다.

주요 기능은 다음과 같습니다.

- 협착 category 26을 class 0으로 변환
- Polygon 좌표 정규화
- Crowd 및 RLE annotation 제외
- 잘못된 Polygon 필터링
- 데이터 분할별 라벨 저장
- 전처리별 Segmentation 라벨 복사

독립 Python 스크립트의 변환 기능은 합성 COCO 데이터로 테스트했습니다.

다만 실제 ARCADE 전체 데이터 변환과 Segmentation 모델 학습·평가는 아직 완료하지 않았습니다.

### 9.2 병변 중심 ROI Crop

**관련 스크립트:** `06B_build_roi_crop_pipeline.py`

정답 annotation의 bbox를 활용해 병변 주변을 Crop하는 파이프라인을 구성했습니다.

가까운 병변을 하나의 그룹으로 묶고, 여백을 포함해 Crop한 뒤 이미지 크기를 640으로 조정했습니다.

이때 Polygon 좌표도 Crop된 이미지의 좌표계에 맞게 다시 계산하도록 했습니다.

하지만 이 방식은 학습 단계에서 정답 위치를 알고 있다는 전제가 필요합니다.

실제 추론에서는 정답 위치를 알 수 없기 때문에, 정답 bbox 기반 Crop의 성능을 곧바로 전체 영상 탐지 성능과 비교할 수 없습니다.

현재는 파이프라인 코드 구현 단계이며, 실제 데이터 실행과 모델 성능 평가는 추가 작업으로 남아 있습니다.

### 9.3 2단계 ROI 재탐지

**관련 스크립트:** `06C_roi_crop_cascade.py`

첫 번째 모델에서 탐지한 bbox를 기준으로 ROI를 추출하고, 두 번째 모델이 확대된 영역을 다시 분석하는 2단계 탐지 구조를 구성했습니다.

전체 흐름은 다음과 같습니다.

**1차 탐지 → 예측 bbox 그룹화 → ROI Crop → 2차 탐지 → 원본 좌표 복원 → NMS**

TP, FP, FN을 계산하는 평가 함수도 작성했습니다.

다만 실제 두 모델을 연결한 추론 결과와 성능 비교는 아직 없습니다.

또한 첫 번째 단계에서 병변을 전혀 탐지하지 못하면 두 번째 탐지 단계로 이어지지 못한다는 구조적 한계가 있습니다.

이 방식을 검증하려면 1차 모델의 누락 병변, Crop 크기, 좌표 복원, 2차 탐지의 오탐 변화 등을 함께 평가해야 합니다.

## 10. 실험 정리 및 향후 개선 방향

이번 프로젝트에서는 여러 전처리와 객체 탐지 모델을 비교하면서 다음과 같은 점을 확인했습니다.

### 전처리와 탐지 성능은 반드시 함께 평가해야 한다

CLAHE는 원본 영상보다 ROI 대비와 경계 밀도를 크게 높였습니다.

하지만 YOLO11n의 최종 mAP50-95는 CLAHE+Gamma에서 가장 높았고, Original과의 차이는 0.006이었습니다.

Faster R-CNN의 30 epoch 비교에서는 오히려 Original 입력이 더 좋은 결과를 보였습니다.

결과적으로 영상 품질 개선과 탐지 성능 개선을 동일하게 볼 수 없다는 점을 배웠습니다.

### 데이터 파이프라인 검증도 모델 학습만큼 중요하다

전처리 이미지를 생성했더라도 학습 폴더로 옮기는 과정에서 검증 이미지가 누락될 수 있었습니다.

입력 데이터 개수와 annotation을 확인하는 작업이 실제 학습에 앞서 필요하다는 점을 경험했습니다.

### 실험 조건과 평가 기준을 명확하게 남겨야 한다

같은 모델에서도 학습 epoch와 체크포인트 선택 기준에 따라 결과가 달랐습니다.

특히 YOLO의 mAP50, mAP50-95와 Faster R-CNN의 VOC AP50는 서로 다른 평가 방식이므로 수치만으로 모델의 우열을 판단하지 않았습니다.

또한 구현한 코드와 실제로 완료한 모델 학습·평가 결과를 구분하는 것이 중요했습니다.

### 앞으로 개선하고 싶은 부분

추가로 진행할 작업은 다음과 같습니다.

- 환자 단위 데이터 분할 및 데이터 누수 점검
- 별도 Test 데이터셋을 이용한 평가
- 여러 Seed를 사용한 반복 실험
- 작은 병변 크기별 탐지 성능 분석
- 공통 평가 조건에서의 모델 비교
- Segmentation과 ROI 기반 2단계 탐지 실험
- 미완료 노트북의 오류 수정과 재실행 검증

현재 결과는 제한된 데이터와 실험 조건을 기준으로 한 것이며, 임상 환경에서의 유효성을 검증한 결과는 아닙니다.

실험 환경과 재현에 필요한 사항은 [재현성 문서](reproducibility.md), 성능 수치와 그래프 출처는 [결과 설명](../results/README.md)에 정리했습니다.
